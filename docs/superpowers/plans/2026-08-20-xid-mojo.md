# xid-mojo 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** `rs/xid` と12バイト値および20文字列を相互変換でき、macOS ARM64 と Linux x86-64 で並行生成できる Mojo 1.0.0 ライブラリを実装する。

**Architecture:** 値表現と base32hex を `id.mojo`、libc 境界を `system.mojo`、machine ID・PID・共有 atomic counter を `generator.mojo` に分離する。利用者は package-level の可変状態ではなく、コピー間で counter を共有する `Generator` を明示的に所有する。

**Tech Stack:** Mojo 1.0.0、Pixi 0.77.0、`crypto = 0.2.0`、Mojo 標準ライブラリ、macOS/Linux libc。

**Spec:** `docs/superpowers/specs/2026-08-20-xid-mojo-design.md`

**Global Constraints:** YAGNI・KISS・DRY を守り、互換 shim、fallback、Python interop、外部コマンド呼び出し、説明コメントを追加しない。各実装変更は失敗するテストを先に確認し、既存の Python/uv 雛形以外の利用者変更を上書きしない。

公開 API は仕様書のシグネチャに固定し、`src/xid/__init__.mojo` は次だけを再公開する。

```mojo
from .generator import Generator
from .id import ID, from_bytes, from_string, nil_id, sort
```

## Interfaces

- `ID` は `Copyable`、`Movable`、`Equatable`、`Hashable`、`Writable` に準拠し、`to_string()`、`bytes()`、`time()`、`machine()`、`pid()`、`counter()`、`is_nil()`、`is_zero()`、`compare()` を提供する。
- package 関数は `from_string(String) raises -> ID`、`from_bytes(Span[Byte, _]) raises -> ID`、`nil_id() -> ID`、`sort(mut List[ID])` とする。
- `Generator` は `Copyable`、`Movable` に準拠し、`Generator() raises`、`new(mut self) raises -> ID`、`new_with_time(mut self, UInt32) -> ID` を提供する。
- 内部の OS 境界は `_unix_seconds() raises -> UInt32`、`_process_id() -> UInt16`、`_hostname_bytes() raises -> List[UInt8]` とする。

**Step 3: strict decoder を実装する**

`_decode_digit()` は ASCII の `0`–`9` と `a`–`v` だけを受け付ける。
`from_string()` は byte length 20を検証し、`digits[19] & 0x0F != 0` を non-canonical として拒否する。
復元式は次にする。

```mojo
b[0] = d[0] << 3 | d[1] >> 2
b[1] = d[1] << 6 | d[2] << 1 | d[3] >> 4
b[2] = d[3] << 4 | d[4] >> 1
b[3] = d[4] << 7 | d[5] << 2 | d[6] >> 3
b[4] = d[6] << 5 | d[7]
b[5] = d[8] << 3 | d[9] >> 2
b[6] = d[9] << 6 | d[10] << 1 | d[11] >> 4
b[7] = d[11] << 4 | d[12] >> 1
b[8] = d[12] << 7 | d[13] << 2 | d[14] >> 3
b[9] = d[14] << 5 | d[15]
b[10] = d[16] << 3 | d[17] >> 2
b[11] = d[17] << 6 | d[18] << 1 | d[19] >> 4
```

長さ、文字、canonicality の全エラーを `Error("xid: invalid ID")` に統一する。

**Step 4: public initializer と現在時刻生成の失敗テストを書く**

test の前に `XID_MACHINE_ID=66051` を設定し、`Generator().new()` の machine ID が `[1, 2, 3]`、時刻が2026年から2100年の範囲であることを検証する。
test 後は元の環境変数を必ず復元し、元が未設定なら `unsetenv()` する。

`Generator()` は次の順に実装する。

1. `getenv("XID_MACHINE_ID")` が存在し、空でなければ `_parse_machine_id_override()` を呼ぶ。
2. 未設定または空なら `_hostname_bytes()` の結果を `_machine_id_from_hostname()` へ渡す。
3. `_process_id()` を取得する。
